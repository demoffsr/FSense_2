# Backend v0.0.1 — Architecture Lock

**Release Date:** January 2026  
**Status:** Foundation Complete  
**iOS Compatibility:** Ready for integration

---

## Scope

Version 0.0.1 establishes the foundational architecture for the FSense backend.
This version provides a working pipeline that produces deterministic JSON payloads
for the iOS FlowerCard UI.

### What IS Included

1. **Complete Pipeline Architecture**
   - `PipelineContext` as single source of truth
   - `BaseAgent` interface for all agents
   - `PipelineOrchestrator` with fixed execution order
   - 10 agent adapters (placeholder implementations)

2. **iOS Integration API**
   - `run_flower_chat(prompt, region)` — Main entrypoint
   - Deterministic JSON response format
   - Success/Error wrapper for iOS error handling

3. **Schema Contract**
   - `FlowerCardPayload` Pydantic schema
   - Complete mapping to iOS Swift models
   - All UI fields populated

4. **Infrastructure**
   - Environment configuration via `.env`
   - OpenAI client abstraction
   - Smoke tests (17 tests passing)

### What is NOT Included

1. **Real AI Logic**
   - Agents return placeholder/mock data
   - No actual OpenAI calls in agent logic
   - Intent detection not implemented

2. **HTTP Server**
   - No FastAPI or REST API
   - Local Python calls only
   - Future: v0.1.0 will add HTTP endpoints

3. **Persistence**
   - No database
   - No conversation history
   - No user sessions

4. **Advanced Features**
   - No async execution
   - No parallel agent processing
   - No caching layer
   - No rate limiting

## Guarantees

### Response Format (GUARANTEED)

Every call to `run_flower_chat()` returns:

```json
// Success
{
  "success": true,
  "data": {
    "header": { ... },
    "meaning": { ... },
    "gifting": { ... },
    "context": { ... },
    "ask_ai": { ... },
    "pipeline_version": "0.0.1",
    "request_id": "uuid"
  }
}

// Error
{
  "success": false,
  "error": "Human-readable message"
}
```

### Agent Execution Order (GUARANTEED)

Agents always run in this exact order:

```
FIA → EIA → RIL → FMRA → CIA → AITB → RFFA → CRI → SRFL → SFA
```

### Schema Stability (GUARANTEED)

The `FlowerCardPayload` schema will not have breaking changes within v0.x.x.
Fields may be added, but existing fields will not be removed or renamed.

### Single Assembler Rule (GUARANTEED)

Only `SFA` (Symbolic Flower Agent) produces the final UI payload.
No other agent writes to `ctx.ui_payload`.
